# 法律材料 OCR

客户端技能版本：document-ocr v0.1.0

## 职责与边界

本技能只执行 OCR 转换和质量控制，不作合同审查、证据评价或其他法律判断。所有识别、临时文件和成果均留在律师自己的客户端；未经用户明确授权，不得把文件、页面图像或识别文本上传到云端服务。

把原始扫描材料转换为三类成果：尽量保持原页面视觉内容的可检索 PDF、带稳定页码标记的文本副本、可审计的逐页质量报告。OCR 文本只是检索和理解辅助，不能替代原图，也不能因识别结果看似通顺而推断缺失文字。

不得覆盖原件，不得启用宏，不得移除电子签名或数字签章后仍把文件描述为原签署件。任务只要求读取扫描内容而不要求生成 OCR 成果时，也执行完整性和关键字段核验，但不额外制造用户未要求的交付文件。

## 1. 探测跨平台能力

先识别 macOS 或 Windows、硬件架构、可用 CPU 与内存，再读取持久环境状态：macOS 使用 `~/Library/Application Support/LegalSkills/environment.json`，Windows 使用 `%LOCALAPPDATA%\LegalSkills\environment.json`。它必须是 JSON 对象，`schema_version=1`、`runtime_version=1.0.0`，并与当前系统和架构一致；`pixi_path`、`manifest_path`、`officecli_path` 必须是固定 `LegalSkills/runtime/1.0.0` 内的绝对真实路径，不能通过符号链接或重解析点逃逸。

`commands` 必须包含 `officecli`、`pdftotext`、`pdftoppm`、`pdfseparate`、`pdfunite` 和 `tesseract`，每项都是首元素为绝对可执行路径的非空字符串数组。`runtime_mode` 缺省或为 `pixi-managed` 时，PDF/OCR 命令必须以 `pixi_path run --locked --no-config --manifest-path <manifest_path>` 开头，Windows ARM64 还必须在 `-x` 前包含 `--platform win-64`。Windows x64 的 `runtime_mode=portable-package` 可让 PDF/OCR 命令直接使用一个绝对可执行路径，但路径必须位于 `%LOCALAPPDATA%\\LegalSkills\\runtime\\1.0.0` 或其已验证的解压环境目录内；不得使用 PATH 回退、相对路径、shell 字符串或越界路径，`pixi_path` 和 `manifest_path` 仍须是该固定 runtime 中的真实文件。拒绝二次展开以及包含 Token、密码、Bearer 或案件路径的污染状态。状态缺失、越界或不一致时停止转换，要求重新执行完整一次性安装提示词；不得回退到 PATH 上的同名工具。

下文出现的 Poppler 和 Tesseract 命令都是逻辑名称。实际执行必须把状态中对应的命令数组作为 argv 前缀，再追加参数；不得拼接 shell 字符串或二次展开。`ocrmypdf`、`qpdf` 等增强工具不在基础运行时中，只有客户端已经安装并独立通过健康检查时才使用。

随后只读探测本地能力：

```text
pdftotext -v
pdftoppm -v
pdfseparate -v
pdfunite -v
tesseract --version
tesseract --list-langs
ocrmypdf --version
qpdf --version
```

`ocrmypdf` 和 `qpdf` 是优先或增强能力；Poppler 的文本提取、页面渲染、拆分与合并，以及 Tesseract 中文 OCR 构成基础能力。至少确认 `eng`、`chi_sim`、`chi_tra` 和 `osd` 中与材料相符的语言可用。任何命令都必须通过实际健康检查，不能仅凭文件存在或 PATH 记录判断可用。

缺少完成本次任务所需的能力时停止转换，列出缺失能力和预计用途。不得在本技能内静默安装、升级或绕过系统安全策略。不得假定 Bash、Homebrew、POSIX 虚拟环境、macOS 字体路径或 Windows 管理员权限存在。

## 2. 建立批次与原件基线

逐一记录输入文件、格式、字节数、修改时间、内容哈希、页数或图片数、来源、版本关系、是否加密以及当前是否存在文字层。区分原始扫描件、已有 OCR 成品、签署件、重复件和工作副本；不要凭文件名判断最新版本。

默认在原件旁建立独立的成果目录和过程目录：

```text
OCR成果/
  <原名>_OCR.pdf
  <原名>_OCR.md
OCR过程文件/
  manifest.json
  质量报告/
  临时页/
```

临时页和中间结果不得散落到原件目录。文件名冲突时生成明确的新版本，不覆盖既有成果。临时目录只能属于当前批次，失败回滚时不得删除其他任务或用户原有文件。

## 3. 逐页判断，不以“有文字”代替“文字有效”

先取得总页数，再逐页判断：可用文字页、纯扫描页、混合页、损坏文字层页或无法判断页。已有少量文字、隐藏文字或可以复制字符，不代表文字层完整有效。

对已有文字层至少检查：字符量与可见内容是否相称、阅读顺序、乱码与重复片段、搜索命中、文本坐标与页面方向，以及姓名、案号、金额、日期、条款编号和否定词等关键字段。发现文字层与原图不一致、只有水印文字、字符异常或检索失效时，把该页视为需要重建，不在旧文字层上直接叠加新文字层。

对扫描页检查方向、裁切、分辨率、重影、淡墨、污损、手写、表格、印章、签名和宽字距竖排文字。页面是否横向只是一项信号，不能机械决定 OCR 引擎或认定识别质量。

## 4. 选择转换路线

优先使用已经通过健康检查的 `ocrmypdf` 在工作副本上生成基础成果。根据页面状态选择保留有效文字、重做损坏 OCR 或强制重建文字层；参数不确定时先读取本机 `ocrmypdf --help`，不得照搬其他版本命令。先在少量代表页验证语言、方向、纠偏和输出质量，再处理全文件。不得直接对原件原地执行。

`ocrmypdf` 不可用但 Poppler 与 Tesseract 基础能力完整时，采用平台无关的分页路线：

1. 用 Poppler 按原页序拆分 PDF，并以适合原稿的小字清晰度渲染需要 OCR 的页面；默认从 300 DPI 起，根据原图质量调整，不盲目升高分辨率。
2. 对已有且验证有效的文字页保留原分页；对扫描或损坏页使用 Tesseract 生成带隐形文字层的单页 PDF，并同时保留该页文本。
3. 按原页序合并单页成果，写入临时输出文件；只有页数、顺序和结构验证通过后才原子改名为最终成果。
4. 把逐页文本按 `## 第 N 页` 标记合并成 UTF-8 Markdown；无法识别的页也必须保留页码和失败说明，不能静默缺页。

不同文件可以并行；同一 PDF 在取得页数和稳定拆分页后，可以按独立页或连续页段受控并行 OCR。并发数根据 CPU、内存、页面尺寸和工具限制确定，不得无上限启动。单个 PDF 的最终合并、成果替换和 manifest 提交必须串行，并使用独立临时文件避免竞争。

疑难页可以改用客户端已经安装且验证过的本地增强 OCR 引擎，但增强引擎不是完成任务的默认前提。不同引擎结果冲突时回看原图；不得用模型猜测补字，也不得手工把推断内容写入隐形文字层冒充 OCR 结果。

## 5. 断点续跑与变更识别

逐页记录源文件哈希、源页码、工具与版本、语言、分辨率、处理参数、状态、文字量、耗时、临时产物和错误。断点续跑只有在源文件哈希、流水线版本、工具版本和影响结果的参数全部一致时才能复用；不得仅凭路径、文件名或“输出已存在”跳过。

每处理完一页或一个稳定页段就原子更新 manifest。失败页单独标记，不得把部分成功写成整份文件成功。参数或原件变化时只使受影响的缓存失效，同时保留旧报告以便追溯。

## 6. 可检索性与视觉验收

OCR 命令返回成功不等于成果合格。每份最终 PDF 至少完成：

1. 重新打开并确认页数、页序、页面尺寸和旋转方向与原件一致。
2. 对所有页面提取文字，生成逐页字符量清单；低文本页必须回看原图，区分“页面本身文字少”和“漏识别”。
3. 用与 OCR 生成路径不同的提取器抽查中文搜索和复制，防止文字层只被部分阅读器识别。
4. 检查文字层与可见文字的位置关系，防止旋转后错位、重复文字层、整页偏移或不可见乱码。
5. 检查 U+2E80–U+2EFF、U+2F00–U+2FDF、U+F900–U+FAFF、U+FE30–U+FE4F 等部首、兼容和竖排字符异常，并检查数字被逐字符插入空格等检索破坏。
6. 逐页渲染比对原件与成果，检查裁切、模糊、压缩损伤、空白页、印章、签名、表格和图片。不得根据单个样本宣称固定 DPI 或压缩参数对所有材料“肉眼无差”。
7. 对姓名、案号、金额、日期、账号、证件号码、条款编号及否定词逐项回看原图。手写、印章覆盖和无法确认内容标为“需人工核对”，不依上下文补全。

签名或印章只能记录为图像中可见，不能由 OCR 成果推断真实、有效或已获授权。最终报告列明输入、输出、实际覆盖页、使用工具、异常页、人工核对项、失败项和剩余限制，不倾倒无必要的全文日志。

## 停止条件

出现以下任一情况，不得声称 OCR 完成：原件打不开或密码未取得；总页数或版本无法确认；输出页数或顺序变化；关键页面方向、裁切或文字层错位；中文语言包缺失；结构检查或第二提取器检查失败；关键字段无法辨认却未标记；只有部分页面成功；成果未重新打开并逐页核验。
